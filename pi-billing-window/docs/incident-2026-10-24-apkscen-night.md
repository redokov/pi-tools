# Инцидент: ночной прогон APKScenTest 24→25.10 не продолжился после сбросов лимитов

## Симптом

Ночная сессия APKScenTest (2026-10-24T18-45-14-236Z) работала до 01:25 лок.,
затем упёрлась в лимит. Сбросы окон 01:51 / 03:51 / 05:51 не дали
продолжения. Ручное «продолжи» только в 09:33.

## Что произошло на самом деле (по armslog + history.csv + jsonl сессии)

| Лок. время | Событие |
|---|---|
| 21:46 | Пользователь взвёл флаг (`repeat=8`, TTL 8 ч) в ночной сессии |
| 23:23:18 | **Ночной агент сам снял флаг**: T11 завершён по стоп-условию, `arm_cont_after_reset.py "$PI_SESSION_FILE" --remove` → `REMOVED`, arms.json = `{}` |
| 23:23:54 | Итоговый отчёт «Ночь T11 завершена по стоп-условию» |
| 23:24 | arm-gone-переход; armslog написал **`reason=ttl-expired` — ЛОЖНО** (TTL был жив ещё ~6 ч; реальная причина — внешнее удаление) |
| 23:48–00:32 | Пользователь дал новые задачи в той же сессии; агент работал |
| 01:25 | Агент упёрся в лимит, замолчал (последний вызов #103 в окне 104) |
| 01:51 / 03:51 / 05:51 | Сбросы окон — флаг снят ещё в 23:23, повторно никто не взводил → продолжения нет |

**Корневая причина — протокольная, не кодовая:** «ночь завершена → disarm»
отработал штатно, но последующие задачи в той же сессии (23:48+) остались без
флага, и никто его не перевзвёл.

## Найденные и исправленные дефекты

1. **Deploy-разрыв.** Коммит 416ec22 (spec-012/013, 24.10 15:01) не был
   задеплоен: рабочая копия расширения была от 16.10. Вдобавок `deploy.ps1`
   содержал устаревший список файлов (`ticker.ts`, удалённый из src; не было
   `wakeups.ts`/`reset.ts`) — даже запуск деплоя дал бы нерабочее расширение.
   **Fix:** список обновлён, деплой выполнен, осиротевший `ticker.ts` удалён
   из рабочей копии, tsc чистый, 202 + 48 + 18 тестов зелёные.
2. **Ложная метка arm-gone.** Внешнее удаление записи из arms.json
   логировалось как `reason=ttl-expired` → дезинформация при диагностике
   (стоила ложной «TTL-теории» всему разбору). **Fix:** отдельная метка
   `reason=external-removal` + тест `testExternalRemovalNotify` (сьют
   arm-gone-notify, 48 passed).
3. **Мусорный wakeups.json.** `~/.pi/agent/pi-billing-window-wakeups.json`
   был записан дев-тестами 24.10 14:39 (утечка изоляции до spec-012 T4;
   точки с дев-якорями, хвост обрывался 03:55). **Fix:** файл удалён;
   с ню-версии тесты пишут wake-таблицу в tmp-каталог.

## Рекомендации (не выполнены, требуют решения)

- **APKScenTest night-prompt:** правило «после стоп-условия/disarm новые задачи
  в той же сессии требуют перевзвода `/cont-after-reset N`» — иначе вечерние
  докрутки остаются незастрахованными.
- **Проверить доставку arm-gone-notify** (23:24): если notify-канал молчал,
  пользователь не узнал, что флаг снят, и продолжал давать задачи «в никуда».
- Рассмотреть: notify при external-removal делать более настойчивым
  (напоминание через N минут, пока сессия владельца жива).
