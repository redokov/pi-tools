# Feature: Spec 017 — boundary-ping (пинг-зонд границы окна: верифицированный reset + якорь нового окна у провайдера)

## Overview

У провайдера wormsoft лимит «5M кредитов в скользящие 2 часа» с ленивым якорем:
**новое окно стартует только от первого запроса** после восстановления лимита.
Локальная модель расширения считает `windowStartedAt = момент reset'а`, а сетка
wake-точек — от первого вызова. Из-за лени расписание провайдера и локальная модель
расходятся:

- **A. Холостой reset:** reset сработал, вызовов долго не было → локальный якорь
  фиктивен; первый реальный вызов якорит окно у провайдера ПОЗЖЕ → следующая
  локальная граница срабатывает РАНЬШЕ реального конца окна → ложный
  `billing:window_reset`, `callsInWindow=0` при живом лимите → внезапный 429;
  `cont-after-reset` шлёт «продолжи» в стену 429.
- **B. Холостой промежуток:** агент простаивает на границе → окно у провайдера
  вообще не запущено → обратный отсчёт врёт, следующий reset непредсказуем.

Фича: на каждой wake-границе слать **дешёвый 1-токенный completion-пинг** к wormsoft
самой дешёвой моделью напрямую (мимо пайплайна pi). Успех (200) = окно реально
перевернулось; сам пинг **якорит новое окно у провайдера на предсказанный момент** —
сетка 2ч становится детерминированной. 429 = окно ещё живое → локальный якорь
корректируется, reset подавляется. Сетевые ошибки — не сигнал об окне → bounded
retry, при повторении — слепой legacy-reset (пинг никогда не блокирует reset навсегда).

## Business Context

- **Problem:** ложные/невовремя `billing:window_reset` после холостых промежутков;
  «продолжи» в стену 429; врущий обратный отсчёт после простоя.
- **Users:** ночные автономные сессии (cont-after-reset, night-run) и пользователь,
  возвращающийся к машине после простоя.
- **Value:** `billing:window_reset` становится верифицированным событием (только
  после подтверждённого провайдером переворота); расписание окна предсказуемо
  независимо от трафика.
- **Success signal:** ноль ложных reset'ов (reset только после пинга-200 или реального
  успешного вызова); после холостого промежутка первый пинг якорит окно точно на
  границе; стоимость пинга ≈ 0.06 кредита из 5 000 000 (1.2e-8 окна).

## Goals

- Каждый auto-reset подтверждён провайдером (200 пинга) либо fallback-ом.
- Пинг якорит новое окно провайдера на момент wake-границы — локальная модель и
  провайдер идут по одной сетке.
- 429-пинг корректирует локальный якорь (re-anchor на firstCallEmittedAt) и
  перепланирует проверку; «продолжи» не летит в живое окно.
- Стоимость пинга пренебрежимо мала; пинг не виден в транскрипте сессии.

## Non-Goals / Out of Scope

- GET /v1/models как бесплатный зонд — НЕ используется: не активирует окно (D-005).
- Пинг после ручного `/settimer 0` / `/billing-reset` — ручной reset остаётся
  слепым (D-006).
- Сокращение grace 60 с в fire-пути после пинга-OK — вне этой версии (follow-up).
- Изменение fire-пути arms, дедупа reset, paced-ретрая — только переиспользование.
- Учёт пинга в callsInWindow / подтверждение пингом cont-after-reset — пинг
  deliberately невидим для этих механизмов.

## User Stories

### US-001: верифицированный reset

**Как** пользователь ночной автономной сессии,
**я хочу** чтобы `billing:window_reset` эмитился только когда лимит провайдера
действительно восстановлен,
**чтобы** «продолжи» и night-run re-drive не срабатывали в стену 429.

**Acceptance Criteria:**
- [ ] На wake-границе сначала пинг; reset+emit только на 200.
- [ ] На 429 reset подавлен, «продолжи» не отправляется, якорь скорректирован.

### US-002: детерминированная сетка окна

**Как** пользователь, вернувшийся к машине после простоя,
**я хочу** чтобы новое окно провайдера стартовало в предсказанный момент (на
wake-границе, а не «когда-нибудь»),
**чтобы** обратный отсчёт и следующая граница были точными.

**Acceptance Criteria:**
- [ ] Успешный пинг якорит окно у провайдера на момент границы; локальная
  wake-таблица перестраивается от момента пинга.
- [ ] После холостого reset'а без вызовов первый пинг восстанавливает сетку.

### US-003: ручная диагностика

**Как** пользователь, хочу вручную проверить живость лимита:
`/ping-wormsoft` шлёт пинг немедленно и показывает статус/латентность/токены,
не трогая состояние окна.

**Acceptance Criteria:**
- [ ] Команда показывает 200/429/ошибку + латентность + usage.
- [ ] Ручной пинг не делает reset, не двигает якорь, не пишет last429At.

### US-004: наблюдаемость и управление

**Acceptance Criteria:**
- [ ] `/billing-ping on|off|status` — включение/выключение/статус (дефолт on;
  off = точное legacy-поведение слепого reset).
- [ ] `/billing-status` показывает последний пинг; history CSV получает строки
  kind="ping"; armslog — события ping:*.

## Functional Requirements

Нумерация FR-017-N. Приоритет Must, если не указано иное.

### FR-017-1 (Must) — пинг на wake-границе гейтит reset

WHEN срабатывает wake-точка границы окна, THE SYSTEM SHALL отправить
completion-запрос к wormsoft (1-токенный, дешёвая модель, напрямую fetch, мимо
пайплайна pi) и ONLY WHEN ответ 200 SHALL выполнить существующий checkAndReset →
`billing:window_reset` → существующий fire-путь SO THAT reset верифицирован
провайдером. IF ответ 429, THE SYSTEM SHALL подавить reset и эмит.

### FR-017-2 (Must) — модель пинга: самая дешёвая, не «на пенсии»

THE SYSTEM SHALL использовать модель `openai/gpt-oss:20b` (5 000 кр/М вход,
4 000 кр/М выход — по прайсу ai.wormsoft.ru/models, без бейджа «на пенсии» и
«без поддержки»), с авто-фолбэком на `wormsoft/agent/low` при модель-ошибке
(400/404) SO THAT стоимость пинга ≈ 0.06 кредита и не зависит от снятия модели
с обслуживания.

### FR-017-3 (Must) — режим стрима: stream:false с авто-фолбэком

THE SYSTEM SHALL слать пинг c `stream:false` (один JSON-ответ, из него usage);
IF шлюз отвергает не-стрим (протокольная ошибка), THE SYSTEM SHALL повторить с
`stream:true` (статус по заголовкам, abort после первого чанка) и закэшировать
рабочий режим в state SO THAT первый живой пинг сам находит рабочий режим и
далее не дёргает фолбэк.

### FR-017-4 (Must) — 429: подавление + коррекция якоря

WHEN пинг вернул 429, THE SYSTEM SHALL: не делать reset; записать last429At и
history-строку kind="429"; IF firstCallEmittedAt существует и позже
windowStartedAt — re-anchor (windowStartedAt := firstCallEmittedAt) и
перестроить wake-таблицу от нового якоря; ELSE — перепланировать пинг через
10 мин (через wake-точку), максимум 12 попыток, после чего notify и остановка
активного зондирования SO THAT «продолжи» не летит в живое окно, а модель
сходится к реальному расписанию провайдера.

### FR-017-5 (Must) — infra-ошибки не блокируют reset

WHEN пинг падает по инфраструктуре (сеть/таймаут/401/5xx/нет конфига), THE
SYSTEM SHALL retry через 2 мин (wake-точка); после 3 подряд — вернуться к
слепому legacy-reset на границе + однократный notify SO THAT сломанный пинг
никогда не оставляет окно без reset'а.

### FR-017-6 (Must) — пинг якорит новое окно

WHEN пинг на границе вернул 200 и reset выполнен, THE SYSTEM SHALL зафиксировать
локальный якорь (firstCallEmittedAt := момент отправки пинга) и перестроить
wake-таблицу от момента пинга SO THAT следующий реальный вызов не создаёт
двойной якорь, а сетка идёт от пинга.

### FR-017-7 (Must) — dedup пинга между процессами

WHEN несколько процессов pi одновременно срабатывают на одну границу, THE
SYSTEM SHALL пинговать так, что результат (статус) записывается в общий state
с маркером границы (ping.lastBoundary), и процесс, видящий свежий результат
своей границы, НЕ отправляет повторный запрос SO THAT в обычном случае один
пинг на границу; параллельный двойной пинг в race-окне секунд допустим
(стоимость ничтожна).

### FR-017-8 (Must) — burned-head probe

WHEN wake-голова сгорела (машина спала через границу, now > точка + 30 мин),
THE SYSTEM SHALL после тихого purge отправить один probe-пинг: 200 → reset
(окно перевернулось во сне — сетка восстанавливается без ручного /settimer);
429 → путь FR-017-4; infra → bounded retry БЕЗ слепого reset (spec 012
FR-012-10 «не стрелять в прошлое» сохраняется) SO THAT включившаяся машина
восстанавливает сетку сама, но не эмитит запоздалых reset'ов вслепую.

### FR-017-9 (Must) — ручной /ping-wormsoft

THE SYSTEM SHALL предоставлять команду `/ping-wormsoft`: немедленный пинг с
отчётом (статус, латентность, usage); диагностический by design — НЕ трогает
windowStartedAt/firstCallEmittedAt/last429At, не делает reset, не шлёт события
окна; пишет history kind="ping" note="manual" и armslog ping:manual; кэширует
рабочий режим/модель как авто-пинг.

### FR-017-10 (Must) — /billing-ping on|off|status

THE SYSTEM SHALL хранить ping.disabled в state (дефолт: включено); `off` —
auto-границы ведут себя в точности как до фичи (слепой checkAndReset на wake);
`status` — сводка (режим, модель, последний результат, retry/streak счётчики).

### FR-017-11 (Must) — пинг невидим для механизмов окна

THE SYSTEM SHALL: пинг не инкрементит callsInWindow, не аккумулирует window*
токены, не эмитит llm:first_call, не подтверждает pending cont-after-reset
(0-токенный/фоновый вызов не съедает флаг — урок инцидента 2026-09-28).

### FR-017-12 (Should) — наблюдаемость

THE SYSTEM SHALL: history kind="ping" (auto ok/infra, manual) и kind="429"
note="ping probe"; armslog ping:ok / ping:429-reanchor / ping:429-unknown-anchor /
ping:429-cap / ping:infra / ping:infra-fallback / ping:manual; строка последнего
пинга в /billing-status.

## Non-Functional Requirements

### NFR-017-1: стоимость

- Пинг ≈ 10 входных + ≤2 выходных токена gpt-oss:20b ≈ 0.06 кредита; даже при
  скрытых reasoning-токенах (сотни) — ≤ единиц кредитов из 5 000 000.

### NFR-017-2: надёжность / тихая деградация

- Пинг никогда не роняет host-процесс: любые ошибки конфига/сети → infra-путь.
- Отсутствие конфига (models.json/auth.json не найдены) = infra-путь → FR-017-5.

### NFR-017-3: exit hygiene

- Все таймеры пинга (retry-точки идут через wake-таблицу; таймаут запроса)
  unref; пинг не держит event loop (spec 003).

### NFR-017-4: latency

- Таймаут запроса 30 с; retry на 429 отсутствует (нужен сырой статус).

## Constraints

- Конфиг: baseUrl из ~/.pi/agent/models.json (providers.wormsoft.baseUrl),
  ключ из ~/.pi/agent/auth.json (wormsoft.key) — читаются напрямую, толерантно.
- Пинг идёт напрямую fetch, НЕ через пайплайн pi (нет транскрипта, нет хуков).
- Переиспользуются: checkAndReset (reset.ts), wake-таблица (wakeups.ts),
  mutateState/lock-паттерны, appendHistory, armsLog, sendNotify.
- Wormsoft API: openai-completions, POST {baseUrl}/chat/completions.

## Decisions (утверждены пользователем в чате)

### D-001: пинг гейтит reset
`billing:window_reset` — только после 200. Подписчики (cont-after-reset,
night-run) срабатывают на верифицированный переворот. Impacts: FR-017-1, US-001.

### D-002: модель — openai/gpt-oss:20b
Самая дешёвая по прайсу без бейджа «на пенсии» (5 000/4 000 за М); явная модель,
не алиас. Резерв: wormsoft/agent/low при модель-ошибке. Impacts: FR-017-2, NFR-017-1.

### D-003: stream:false с авто-фолбэком на stream:true
Первый пинг определяет рабочий режим; режим кэшируется в state (ping.mode).
Impacts: FR-017-3.

### D-004: /ping-wormsoft — ручная диагностика
Не трогает состояние окна. Impacts: FR-017-9, US-003.

### D-005: GET /v1/models не использовать
Не активирует биллинговое окно у провайдера. Impacts: Non-Goals.

### D-006: /settimer 0 без пинга
Ручной reset остаётся слепым; пользователь у клавиатуры. Impacts: Non-Goals.

### D-007: dedup через общий state, без firelease
Вместо аренды firelease — маркер ping.lastBoundary в state: процесс, видящий
свежий результат своей границы, не пингует повторно. Race-окно даёт редкий
двойной пинг (стоимость ничтожна); смерть пингующего в полёте автоматически
покрывается соседним процессом (нет TTL-ожидания). Impacts: FR-017-7.

### D-008: infra → bounded retry → слепой fallback
3 подряд infra → legacy-reset + notify. Пинг не блокирует reset навсегда.
Impacts: FR-017-5.

### D-009: burned-head → одиночный probe-пинг
200 → reset (восстановление сетки после сна без ручного /settimer); infra на
burned-head НЕ даёт слепого reset (spec 012 сохраняется). Impacts: FR-017-8.

| Ложные reset (reset при живом окне) | 0 при включённом пинге |

## Risks and Mitigations

| Risk | Mitigation |
|---|---|
| Шлюз не поддерживает stream:false | авто-фолбэк + кэш режима (D-003) |
| gpt-oss:20b снят с обслуживания | фолбэк-модель + модель-ошибка = infra → notify |
| Скрытые reasoning-токены дорожают | max_tokens=2 капит; контроль usage в history |
| Ключ/формат auth.json изменился | infra-путь → слепой fallback не оставляет окно без reset |
| Двойной пинг в race-окне | допустимо (стоимость), документировано (D-007) |

## Glossary

- **Пинг:** 1-токенный completion-запрос к wormsoft напрямую, мимо пайплайна pi.
- **Граница (boundary):** wake-точка = якорь + windowMs + WAKE_MARGIN_MS.
- **Ленивый якорь провайдера:** новое окно стартует от первого запроса после
  восстановления лимита.
- **Re-anchor:** коррекция windowStartedAt := firstCallEmittedAt по 429-пингу.
- **Blind/слепой reset:** reset без подтверждения (legacy-поведение spec 012).
