# ТЗ: Настройка репозитория pi-tools для c:\tools

## Общая цель
Настроить папку `c:\tools` как Git-репозиторий с remote `git@github.com:redokov/pi-tools.git`, содержащий 3 инструмента:
1. **pi-billing-window** - отслеживание 2-часового биллингового окна wormsoft
2. **pi-remote** - веб-терминал для pi-сессий через Tailscale
3. **pi-transcribe** - транскрибация аудио/видео через wormsoft API

---

## Задача 1: Инициализация Git и настройка remote
**Агент:** general-purpose
**Описание:** Инициализация git, настройка remote, первый коммит

### Шаги:
1. `cd c:/tools && git init`
2. `git remote add origin git@github.com:redokov/pi-tools.git`
3. Проверить: `git remote -v`
4. Настроить user.name/user.email если нужно

### Критерии готовности:
- `git status` показывает файлы трех инструментов
- `git remote -v` показывает правильный origin

---

## Задача 2: Создание .gitignore для монорепозитория
**Агент:** general-purpose
**Описание:** Создать корневой .gitignore, игнорирующий node_modules, билды, логи каждого инструмента

### Шаги:
1. Проанализировать существующие .gitignore в pi-billing-window
2. Создать корневой .gitignore с правилами для всех трех инструментов
3. Учесть: node_modules/, dist/, build/, *.log, .env, *.tmp.*, .DS_Store, .vscode/, .idea/, out/, server.log, *.bak.*

### Критерии готовности:
- `git status` не показывает node_modules, логи, билды
- Только исходный код и конфигурационные файлы в индексе

---

## Задача 3: Создание README.md для репозитория
**Агент:** general-purpose
**Описание:** Написать общий README с описанием трех инструментов, инструкциями по установке и запуску

### Шаги:
1. Прочитать README каждого инструмента
2. Написать общий README.md в корне c:/tools
3. Структура:
   - Название репозитория
   - Список инструментов с кратким описанием
   - Требования (Node.js версия, pi версия)
   - Установка зависимостей (по одному на каждый инструмент)
   - Сборка каждого инструмента
   - Запуск каждого инструмента
   - Тестирование
   - Структура репозитория
   - Ссылки на документацию каждого инструмента

### Критерии готовности:
- README.md в корне репозитория
- Содержит актуальные инструкции для всех трех инструментов

---

## Задача 4: Первый коммит и пуш
**Агент:** general-purpose
**Описание:** Закоммитить все изменения и запушить на GitHub

### Шаги:
1. `git add .`
2. `git commit -m "Initial commit: pi-tools monorepo with 3 extensions"`
3. `git push -u origin main` (или master)
4. Проверить на GitHub, что все файлы загрузились

### Критерии готовности:
- Пуш прошел без ошибок
- На github.com/redokov/pi-tools видно все 3 папки инструментов
- README.md отображается на главной странице репозитория

---

## Задача 5: Проверка инструкций запуска (верификация)
**Агент:** general-purpose
**Описание:** Проверить, что инструкции из README работают для каждого инструмента

### Шаги:
1. Для pi-billing-window: `npm install && npm run build && npm test`
2. Для pi-remote: `npm install && npm start` (проверить запуск сервера)
3. Для pi-transcribe: `npm install && npm run build && npm test`
4. Если есть проблемы - обновить README

### Критерии готовности:
- Все три инструмента собираются и запускаются без ошибок
- README обновлен при необходимости

---

## Примечания
- Если при пуше потребуется SSH ключ - вывести его публичную часть, пользователь добавит в GitHub
- Каждую задачу выполнять отдельным агентом для отслеживания
- Не использовать длинные таймауты - разбивать на мелкие шаги
