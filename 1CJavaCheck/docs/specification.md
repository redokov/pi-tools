# Спецификация: обработка «Проверка доступности Java» (JavaCheck)

## 1. Назначение

Внешняя обработка 1С:Предприятие (EPF) для проверки того, что **пользователю,
под которым запускается сервер 1С**, доступна Java (`java.exe`).

Проверка выполняется на стороне сервера 1С, то есть от имени учётной записи
службы сервера (`rphost.exe`), а не от имени пользователя, работающего в клиенте.
Именно это отвечает на исходный вопрос: «доступна ли джава пользователю сервера 1С
на `1c-sql-srv`».

## 2. Сценарий использования

1. Администратор заходит в базу 1С на сервере.
2. Открывает обработку `JavaCheck.epf`.
3. Нажимает кнопку **«Проверить»**.
4. В окне сообщений появляется:
   - `Джава доступна` — если Java найдена и запускается;
   - `Джава недоступна` — иначе;
   - строка `Детали: ...` с расшифровкой (пользователь ОС, JAVA_HOME, путь к java.exe,
     код возврата и вывод `java -version`).

## 3. Функциональные требования

| ID | Требование |
|----|-----------|
| FR-1 | Кнопка «Проверить» на форме обработки. |
| FR-2 | Проверка выполняется в серверном контексте (`&НаСервере`), не на клиенте. |
| FR-3 | Определяется имя пользователя ОС, от которого выполняется проверка (`whoami`). |
| FR-4 | Определяется `JAVA_HOME` и наличие `<JAVA_HOME>\bin\java.exe`. |
| FR-5 | Выполняется поиск `java.exe` в каталогах переменной `PATH`. |
| FR-6 | Выполняется `java -version`; анализируется код возврата и наличие слова `version` в выводе. |
| FR-7 | Итог выводится сообщениями: «Джава доступна» / «Джава недоступна» + детали. |
| FR-8 | Ошибки выполнения команд ОС не прерывают работу, а попадают в детали. |
| FR-9 | Обработка ничего не изменяет в базе и в файловой системе (кроме временного файла вывода). |

## 4. Нефункциональные требования

- Время проверки — единицы секунд (4 команды `cmd`).
- Совместимость: 1С:Предприятие 8.3.24+ (формат выгрузки 2.17).
- Никаких внешних компонент, COM-объектов и `JavaComponent` — только штатные
  `ЗапуститьПриложение`, `Новый Файл`, `ЧтениеТекста`.
- Код соответствует стандартам 1С (`std499` — перехват исключений, bslls без ошибок).

## 5. Техническая реализация

### Модуль объекта (`src/JavaCheck/Ext/ObjectModule.bsl`)

| Метод | Назначение |
|-------|-----------|
| `ПроверитьДоступностьДжавы()` | Основной API: собирает данные ОС и анализирует их. Возвращает структуру `Доступна, Версия, ПутьКJava, Пользователь, Детали`. |
| `ПроверитьПоДанным(Пользователь, ЗначениеJavaHome, ЗначениеPath, КодВозвратаJavaVersion, ТекстВерсииJava)` | Анализ уже собранных данных (используется тестами, позволяет проверить логику без обращения к ОС). |
| `СобратьДанныеПроверки()` | Выполняет `whoami`, `echo %JAVA_HOME%`, `set PATH`, `java -version` через `cmd /c` с выводом во временный файл. |
| `ВыполнитьКомандуОС(Команда)` | Запуск команды через `ЗапуститьПриложение(..., Истина, КодВозврата)`, чтение вывода (cp866 → windows-1251 → UTF-8), удаление временного файла. |

Критерий доступности: `КодВозврата = 0 И в выводе java -version есть "version"`.
Наличие файла `java.exe` используется только для информативности деталей.

### Модуль формы (`.../Form/Module.bsl`)

- `&НаКлиенте Proverit(Команда)` — вызывает серверную функцию и выводит сообщения.
- `&НаСервере ПроверитьНаСервере()` — `РеквизитФормыВЗначение("Объект").ПроверитьДоступностьДжавы()`.
  Именно этот вызов исполняется на сервере 1С (учётная запись службы).

## 6. Критерии приёмки

| ID | Критерий | Статус |
|----|----------|--------|
| AC-1 | В окне сообщений выводится «Джава доступна» или «Джава недоступна» | ✅ проверено (headless) |
| AC-2 | Детали содержат пользователя ОС, JAVA_HOME, путь к java.exe, вывод `java -version` | ✅ проверено |
| AC-3 | При отсутствии Java выводится «Джава недоступна» (3 негативных сценария) | ✅ проверено |
| AC-4 | Обработка собирается платформой без ошибок, bslls — 0 ошибок | ✅ проверено |
| AC-5 | Открывается и вызывается из базы `Srvr=localhost;Ref=dev_erpapk_demo` | ✅ проверено (COM) |
| AC-6 | Кнопка в GUI от имени службы сервера | ✅ проверено — «Пользователь ОС: nt authority\system», `Джава доступна` (скриншот `artifacts/gui_result.png`) |

## 7. Ограничения и зависимости

- Требуется разрешение на `ЗапуститьПриложение` и файловые операции:
  в **безопасном режиме** (например, при программном создании обработки через
  `ВнешниеОбработки.Создать` без отключения безопасного режима) проверка вернёт
  «Джава недоступна» с пояснением об ошибке. При открытии обработки пользователем
  вручную безопасный режим не применяется.
- Проверка показывает окружение **процесса**, выполняющего код: для `&НаСервере` —
  учётная запись службы 1С; для внешнего соединения COM — учётная запись клиента.

## 8. Проверенные факты по тестовому стенду

- Служба `1C:Enterprise 8.5 Server Agent (x86-64)` → `SERVICE_START_NAME = LocalSystem`.
- **GUI-прогон (интерактивный десктоп, `1cv8.exe ENTERPRISE /Execute JavaCheck.epf`):
  нажата кнопка «Проверить» → в окне сообщений `Джава доступна`, в деталях
  `Пользователь ОС: nt authority\system` → код исполнялся на сервере от имени службы.**
- Машинные переменные (`HKLM\...\Session Manager\Environment`), наследуемые LocalSystem:
  - `JAVA_HOME = C:\Program Files\BellSoft\LibericaJDK-11-Full\`
  - `PATH` содержит `...\LibericaJDK-11-Full\bin` и `...\LibericaJRE-11\bin`
- Прогон тех же команд с машинным (без пользовательских) окружением:
  `java -version` → `openjdk version "11.0.20" 2023-07-18 LTS`, код возврата `0`.
- Вывод: **Java доступна учётной записи сервера 1С** на этом хосте.
