# План работ — 1CJavaCheck (SDD tasks)

Проект: внешняя обработка (EPF) «Проверка доступности Java» для сервера 1С.
Итоговый файл: `c:/Tools/1CJavaCheck/JavaCheck.epf`.

## Критерий успеха

Открыть обработку в базе → нажать «Проверить» → в окне сообщений
«Джава доступна» / «Джава недоступна» + детали.

## Технический принцип

Проверка выполняется в серверном контексте (`&НаСервере`), то есть от имени
учётной записи службы сервера 1С (`rphost.exe`). Команды: `whoami`,
`echo %JAVA_HOME%`, `set PATH`, `java -version` — через `ЗапуститьПриложение`
с выводом во временный файл. Критерий: код возврата `0` и слово `version` в выводе.

## Ключевые находки (грабли)

1. **`JavaComponent`/`ПолучитьПеременнуюСреды`/`Пауза` — не существуют в BSL.**
   Первый вариант кода был некомпилируемым. Решение: только `ЗапуститьПриложение` + `cmd`.
2. **EPF — не zip, а проприетарный контейнер 1С** (магия `FF FF FF 7F`).
   Собирать только через платформу (`epf-build`), не «вручную».
3. **`ВнешниеОбработки.Создать()` включает безопасный режим** →
   `Новый Файл` падает с «Установлен безопасный режим». В тесте:
   `Create(EPF, False)`.
4. **Структура, созданная в COM-соединении, не приходит в модуль как `Тип("Структура")`** —
   параметр молча игнорировался (негативные тесты проходили «успешно» вхолостую).
   Решение: отдельный API `ПроверитьПоДанным(...)` на примитивах.
5. **Пустой блок `Исключение` — ошибка bslls (`MissingCodeTryCatchEx`)**.
   По `std499` текст ошибки сохраняется через `ПодробноеПредставлениеОшибки()`.
6. **Логин в тестовой базе — буквально `Администратор (ОрловАВ)`**, не `Администратор`
   и не `ОрловАВ`. Пароль пустой.
7. **Кириллица в COM-вызовах** — передавать только через `\uXXXX`-эскейпы
   в Python-литералах; иначе имя метода приходит искажённым.
