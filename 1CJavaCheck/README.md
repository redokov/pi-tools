# 1CJavaCheck — проверка доступности Java для сервера 1С

Внешняя обработка 1С:Предприятие, которая определяет, **доступна ли Java
пользователю, под которым запускается сервер 1С** (учётная запись службы `rphost.exe`).

## Быстрый старт

1. Взять готовый файл: **`JavaCheck.epf`** (в корне проекта).
2. В 1С:Предприятие: `Файл → Открыть` → выбрать `JavaCheck.epf`.
3. Нажать кнопку **«Проверить»**.
4. В окне сообщений появится:

```
Джава доступна
Детали: Пользователь ОС: LocalSystem; JAVA_HOME: C:\...\LibericaJDK-11-Full;
java.exe в JAVA_HOME: C:\...\bin\java.exe; java.exe в PATH: ... (проверено каталогов: 23);
java -version: код возврата 0; вывод java -version: openjdk version "11.0.20" ...
```

или

```
Джава недоступна
Детали: ... (причина: JAVA_HOME не задана / java.exe не найден / код возврата 1)
```

Проверка идёт в серверном контексте (`&НаСервере`), поэтому в строке
«Пользователь ОС» будет учётная запись службы сервера 1С, а не ваша.

## Сборка из исходников

```powershell
powershell.exe -NoProfile -File "C:\MyProjects\PiPack\skills\1c\epf-build\scripts\epf-build.ps1" `
  -SourceFile "src/JavaCheck.xml" `
  -OutputFile "JavaCheck.epf" -Checks off
```

Перед сборкой — статический контроль BSL (MCP `bsl-ls`, `bsl_analyze` по каталогу `src`):
должно быть 0 ошибок.

## Тестирование

```bash
python tests/test_epf_headless.py              # 5 headless-проверок (COM), итог: все пройдены
powershell -File tests/gui_click_test.ps1      # GUI: открыть EPF, нажать «Проверить», снять сообщения
powershell -File tests/check_server_account_env.ps1
```

GUI-тест требует интерактивного десктопа; клиент 1С стартует ~40 с (большая демо-база),
поэтому в скрипте ожидание кнопки до 180 с. Результаты: `artifacts/gui_result.png`
(скриншот окна с сообщениями) и `artifacts/gui_result.txt` (транскрипт).

Фактический результат GUI-прогона на `dev_erpapk_demo`:

```
Джава доступна
Детали: Пользователь ОС: nt authority\system; JAVA_HOME: C:\Program Files\BellSoft\LibericaJDK-11-Full; ...
java -version: код возврата 0; openjdk version "11.0.20" 2023-07-18 LTS
```

`nt authority\system` — подтверждение, что проверка шла на сервере от имени службы 1С.

Тест-API подключается к базе `Srvr="localhost";Ref="dev_erpapk_demo"`,
пользователь `Администратор (ОрловАВ)`, пароль пустой, и создаёт обработку с
отключённым безопасным режимом (`Create(EPF, False)`) — иначе файловые операции
и `ЗапуститьПриложение` запрещены платформой.

## API модуля объекта

| Метод | Назначение |
|-------|-----------|
| `ПроверитьДоступностьДжавы()` | Основной: собрать данные ОС и проверить Java. Возвращает `Структура(Доступна, Версия, ПутьКJava, Пользователь, Детали)`. |
| `ПроверитьПоДанным(Пользователь, ЗначениеJavaHome, ЗначениеPath, КодВозвратаJavaVersion, ТекстВерсииJava)` | Только анализ переданных данных (тесты, повторная проверка). |
| `СобратьДанныеПроверки()` | Сбор данных командами ОС. |

## Ограничения

- Нужны разрешённые `ЗапуститьПриложение` и файловые операции. В **безопасном режиме**
  (например, если обработку создаёт другая программа через `ВнешниеОбработки.Создать`
  без отключения безопасного режима) проверка вернёт «Джава недоступна» с пояснением.
  При ручном открытии файла пользователем безопасный режим не применяется.
- Проверяется окружение того процесса, который исполняет код: для `&НаСервере` —
  служба сервера 1С, для COM-внешнего соединения — процесс клиента.
