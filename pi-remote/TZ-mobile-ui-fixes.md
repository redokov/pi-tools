## 0. Контекст и результаты анализа

Терминальная страница сейчас — голый xterm.js v6 + FitAddon без мобильной обвязки.
Из README (раздел 5.8) следует, что раньше в UI были и были **утеряны при рефакторинге**:

| Фича | Было (README 5.8) | Стало |
|---|---|---|
| Кнопка «↓ Bt» | показ при отрыве от дна, скрытие на дне, проверка каждые 500 мс | отсутствует |
| Виртуальная клавиатура | Esc, Tab, стрелки, Ctrl+C, ↓ Bt | отсутствует |
| Принудительный скролл к курсору при вводе | `buf.viewportY = length - rows` после `onData` | отсутствует |

Бандл `static/xterm.js` — **версия 6**. Механизм бага №1 (подтверждено по коду бандла):
при IME-композиции xterm двигает helper-textarea к composition view
(`updateCompositionElements` → `left/top = композиционный прямоугольник`, ширина по rect).
Когда строка ввода дорастает до правого края экрана (TUI pi держит курсор у низа),
мобильный браузер панорамирует контейнер по горизонтали, чтобы показать каретку.
Видимый эффект: контент уезжает вправо («текст отображается справа от окна»),
после пробела (commit композиции) — возвращается влево. Горизонтальный pan
не блокируется `overflow:hidden` — Android Chrome скроллит скрытые контейнеры.

## Задача 1. Фикс ввода текста на мобильных (горизонтальный pan при наборе)

### 1.1. Причина
1. IME-композиция рендерится в позиции helper-textarea и растёт вправо за край вьюпорта.
2. Браузер «помогает» и панорамирует страницу / `.xterm-viewport` по горизонтали.
3. После commit (пробел) композиция очищается — pan сбрасывается, контент прыгает.

### 1.2. Реализация (комбинированная)
1. **Viewport-meta:** `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover, interactive-widget=resizes-content">`
   (клавиатура сжимает layout, а не перекрывает его — заодно чинит позицию низа UI).
2. **Запрет горизонтального дрейфа:** клампинг `scrollLeft` на всех скроллимых уровнях:
   ```js
   function clampHScroll(el) { if (el && el.scrollLeft !== 0) el.scrollLeft = 0; }
   document.addEventListener('scroll', function (e) {
     var t = e.target;
     if (t === document.scrollingElement || (t && t.classList && t.classList.contains('xterm-viewport'))) clampHScroll(t);
   }, true);
   setInterval(function () { clampHScroll(document.scrollingElement); }, 250); // подстраховка
   ```
3. **CSS-страховка:** `#x { overflow: hidden; }`, `#x .xterm { touch-action: pan-y; }`
   (вертикальный скролл и pinch разрешить, горизонтальный pan жестом — отключить).
4. **Скролл к курсору при вводе** (возврат фичи из README 5.8): после `onData` —
   `viewportY = max(0, buffer.length - rows)`. Курсор у низа экрана → композиция
   стартует в видимой зоне, pan не нужен.

### 1.3. Критерии приёмки
- [ ] Набор «привет мир тест 123» (RU+EN, с пробелами) в pi TUI: `scrollLeft` страницы и `.xterm-viewport` === 0 на каждом шаге (проверяется e2e T1).
- [ ] Смещение `getBoundingClientRect().left` у `.xterm-screen` в процессе набора ≤ 2px.
- [ ] Курсор виден при наборе у нижней строки (композиция не уходит за край).
- [ ] Десктоп-поведение не регрессировало (мышь, клавиатура, выделение).

## Задача 2. Кнопка «↓ Bt» + стабилизация при повороте экрана

### 2.1. Симптом
После смены ориентации телефона видна середина скроллбака; до свежего вывода скроллить долго.

### 2.2. Причина
`fit.fit()` при повороте меняет rows; xterm сохраняет старый `viewportY` (или абсолютный
индекс, который после изменения rows перестаёт означать «низ»). Автопривязки к низу нет.

### 2.3. Реализация
1. **Кнопка «\u2193 Bt»** (возврат из README 5.8 + улучшения):
   - fixed, правый нижний угол, над областью клавиатуры, 44×44px, тёмная тема, `safe-area-inset`;
   - показывается при отрыве от дна: `viewportY < buffer.length - rows - 1`;
   - скрыта на дне; тап → `viewportY = buffer.length - rows` + скрыть;
   - проверка позиции: `setInterval(500)` (README: `onScroll` не срабатывает при `term.write()`) + мгновенная проверка после `fit()` и поворота.
2. **Stick-to-bottom при ресайзе (РЕШЕНО: всегда к дну при повороте):** после любого
   ресайза/поворота — `fit()` → `viewportY = buffer.length - rows` (к дну) безусловно.
   Исключение — ресайз от открытия/закрытия системной клавиатуры (`visualViewport.resize`
   без смены ориентации): там сохраняем текущую позицию чтения, чтобы не прыгать
   при наборе текста. Триггеры: `window.resize`, `orientationchange`,
   `visualViewport.resize`, c дебаунсом ~150 мс и повторным `fit()` (double-rAF)
   после смены ориентации. Если пользователь был выше дна — после поворота он
   на дне, но кнопка «\u2193 Bt» ему и не нужна; место чтения он вернёт скроллом
   (жертва осознана и принята).
3. **Скролл к курсору при вводе** — см. п. 1.2.4 (та же фича закрывает «ввод в середине экрана»).

### 2.4. Критерии приёмки
- [ ] Поворот экрана в любой позиции → после поворота находимся на дне (e2e T3, безусловно).
- [ ] Открытие/закрытие клавиатуры НЕ сбрасывает позицию чтения (visualViewport-ресайз исключён из «всегда к дну»).
- [ ] Новый вывод PTY при нахождении на дне продолжает автопрокрутку.
- [ ] Кнопка не перекрывает последнюю строку TUI (отступ от нижнего края ≥ 12px, учёт safe-area).

## Задача 3. Виртуальная клавиатура специальных клавиш

### 3.1. Симптом
На мобильной клавиатуре нет Esc, Tab, стрелок, Ctrl — управление pi TUI с телефона ограничено.

### 3.2. Реализация
1. **Кнопка-переключатель «\u2328 Keys»** в тулбаре `#bar` — показывает/прячет панель клавиш.
2. **Панель клавиш** — fixed внизу, над системной клавиатурой (или у низа экрана, когда она скрыта),
   2 ряда, горизонтальный скролл при узком экране, тач-таргеты ≥ 44px, `user-select:none`,
   `touchstart` c `preventDefault()` (не ронять фокус xterm).

| Кнопка | Байты в PTY | Примечание |
|---|---|---|
| Esc | `1b` | |
| Tab | `09` | |
| ↑ ↓ ← → | `1b 5b 41/42/43/44` | |
| Home / End | `1b 5b 48` / `1b 5b 46` | |
| PgUp / PgDn | `1b 5b 35 7e` / `1b 5b 36 7e` | история/скролл в pi |
| Enter | `0d` | |
| Ctrl+C | `03` | прервать процесс / очистить ввод — в один тап |
| Ctrl+D | `04` | EOF / выход |
| Ctrl+Z | `1a` | suspend |
| Ctrl+U | `15` | стереть строку до курсора |
| Ctrl+R | `12` | поиск по истории |
| Ctrl+L | `0c` | очистить экран |
| ↓ Bt | — | дубль кнопки из задачи 2 в правом ряду панели |

3. **Отправка:** та же функция `sendInput(d)`, что и у `xterm.onData` (WS `{type:'in', data:base64}`) — вынести в общую функцию.
4. **Escape-безопасность исходника:** последовательности — строками `'\x1b[A'` и т.п., стрелки в лейблах — `'\u2191'` и т.д. (файл остаётся ASCII).
5. **Состояние:** панель скрыта по умолчанию; выбор пользователя помнить в `localStorage`.

### 3.3. Критерии приёмки
- [ ] Тап по каждой кнопке (включая все 6 Ctrl-комбинаций) отправляет в WS точную последовательность из таблицы (e2e T4: перехват `ws.send` в странице).
- [ ] Панель не перекрывает ввод pi TUI: при открытой клавиатуре панель выше неё; терминал рефиттится (`visualViewport`).
- [ ] Фокус xterm не теряется при тапах по кнопкам (ввод с системной клавиатуры продолжается без повторного тапа в терминал).

## Риски и откат

- Риск: CSS `interactive-widget` поддерживается с Chrome 108 — на старых Android панель может перекрывать низ. Митигируется ручным чек-листом; деградация не хуже текущего состояния.
- Риск: клампинг `scrollLeft` может конфликтовать с будущими горизонтальными фичами xterm — локализовать в терминальной странице, не трогать `static/`.
- Откат: восстановить `server.js.bak.<timestamp>` (создаётся на этапе 1).
- Спорные места зафиксированы в разделе «Открытые вопросы» — все закрыты.

### 3.4. Реализация Ctrl — РЕШЕНО (вариант A: готовые комбинации)

|---|---|---|

| Ctrl+D | `04` | EOF / выход |
| Ctrl+Z | `1a` | suspend |

| Ctrl+R | `12` | поиск по истории |
| Ctrl+L | `0c` | очистить экран |

Кодирование для справки: Ctrl+X в терминале — байт `ord(X) & 0x1f`. Если в будущем
